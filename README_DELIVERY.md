# Обновление приветствий и рассылок

## Запуск на хостинге

Python 3.12. Установите зависимости: `pip install -r requirements.txt`.
Команда запуска: `python run.py`. Прямой запуск `python simple_working_bot.py`
использует тот же код. Одновременно запускайте только одну копию с одним токеном.

Задайте `BOT_TOKEN`, `CHANNEL_ID`, `ADMIN_IDS` (ID через запятую) во вкладке
Environment хостинга либо скопируйте `.env.example` в `.env` и заполните значения.
Environment имеет приоритет над `.env`. Токен в исходниках отсутствует.
`python check_connection.py` проверяет только getMe, не отправляет сообщения
и не забирает обновления. При неверном токене процесс запуска завершается с ошибкой.

Архив обновления содержит только код. При загрузке сохраните существующие JSON
и базы, а также заполненный `.env`. Не переносите старые `bot.py`/`working_bot.py`
в команду Startup: это другие реализации, они не являются точкой запуска обновления.

### Обновление через Botkeep

Рабочие JSON, базы и логи исключены из текущей версии Git. Для обновления
существующего бота выбирайте **Merge files**: файлы, которых нет в репозитории,
останутся в каталоге приложения. Режим **Replace files** очищает каталог и
не подходит для обновления поверх рабочей базы.

Перед первой миграцией со старой версии остановите бота и сохраните копию всех
JSON, `.db` и `.sqlite3`. При обычном `git pull` удаление ранее отслеживаемых
файлов из репозитория может удалить их из рабочей копии: восстановите данные
из резервной копии до запуска. Импорт **Merge files** и настоящий `git pull`
имеют разное поведение, это не взаимозаменяемые команды.

Включайте **Pull before Start / Restart** только после сохранения правильного
режима импорта. Если список подписчиков уже заменился старой копией, восстановите
объединение известных ID из резервных копий, не заменяя остальные файлы состояния
и не сбрасывая `blocked`, `opted_out` и историю доставок.

## Кто получает сообщения через неделю

- Личное сообщение боту, «Запустить» или подтверждённый Telegram
  `write_access_allowed` регистрирует открытый диалог. Недельного срока давности нет.
- Заявка в канал, её одобрение и членство в канале не дают постоянного доступа
  к личке. Временный `user_chat_id` работает до обработки заявки и максимум пять
  минут. Бот использует запас в одну минуту, учитывает дату самой заявки.
- Кнопка «Получать сообщения от бота» открывает ссылку на бота. Человек должен
  нажать «Запустить» или отправить личное сообщение. Перехода по ссылке недостаточно.
- Старые `started_users.json` мигрируют как подтверждённые диалоги.
  Старые `subscribers.json` сохраняются, но сами по себе не доказывают разрешение.
  Число доступных диалогов видно в разделе «Рассылки».
- Успешная отправка проверяемого поста сохраняется как наблюдение доступности
  (`delivery_status=available`), но не подделывает `/start` и не означает вечного
  разрешения. Следующие рассылки учитывают это наблюдение и новые ответы Telegram.
- `/stop` или `/unsubscribe` выключает рассылки и отложенные сообщения.
  `/start` включает будущие сообщения снова. Уже отменённая цепочка автоматически
  не повторяется. Блокировка Telegram исключает получателя без удаления истории.

Чтобы подключить старых участников, разместите в канале ссылку
`https://t.me/ИМЯ_БОТА?start=welcome` с понятным предложением получать сообщения.
Сам бот не публикует это приглашение и не запускает рассылку при обновлении.

## Надёжная доставка

### Проверка старых диалогов без повторов

После обновления откройте **«Рассылки → Проверить получателей последнего поста»**.
Бот возьмёт сохранённое содержимое последней завершённой рассылки и покажет
предпросмотр. В него попадут ранее не включённые адресаты с неизвестным доступом
и новые доступные диалоги. Блокировки, отписки, удалённые аккаунты и записанные
явные отказы Telegram исключаются. Без кнопки **«Отправить рассылку»** отправки нет.

Кому исходный пост уже отправлялся или чья отправка была зарезервирована/прервана
с неизвестным результатом, повтор не назначается. История учитывается по исходному
заданию и всем его дополнительным проверкам, в том числе после перезапуска.
Повторное подтверждение проверки не создаёт дублей. Новые подписчики, появившиеся
после предпросмотра, в эту проверку автоматически не добавляются.

Для нового поста в предпросмотре есть отдельная галочка
**«Разово проверить старые диалоги»** — по умолчанию выключена. Ежедневное расписание
автоматически неизвестные диалоги не проверяет. Доставка проверяется самим постом,
а не дополнительным техническим сообщением. Включение галочки не означает, что
Telegram разрешит отправку каждому сохранённому ID.

Отчёт теперь показывает общее число записей, число включённых в конкретную отправку,
доставки, необходимость `/start`, явные блокировки, удалённые аккаунты, другие отказы,
неизвестный результат и исключения до отправки. `403` сам по себе больше не означает
«пользователь заблокировал»: сохраняются код, описание, время и источник причины.
Старые отметки `blocked=true` без описания сохраняются и показываются отдельно,
а не молча сбрасываются.

Дата в статистике означает добавление в базу бота, а не подтверждённую Telegram
дату вступления в канал. Статистика отдельно показывает доступность рассылки.

- Активные приветствия ставятся в атомарно сохраняемую очередь.
  Задержки считаются от заявки, а для прямого первого запуска — от запуска.
  Недельные задания сохраняются после перезапуска. Долгие задания пользователей
  без открытой лички имеют статус «ждут запуска»; /start разблокирует их.
- Ввод задержек: «Приветствия → список → приветствие → задержка → вручную»;
  например, `7 дней` (максимум 30 дней).
- Общая скорость отправки — до 20 сообщений/сек, в одну личку — не чаще
  одного сообщения за 1.05 секунды. HTTP 429 учитывает `retry_after` для всего бота.
- Прогресс рассылки и подтверждённые ID сохраняются в SQLite. После перезапуска
  очередь продолжает ещё не отправленные сообщения. При таймауте, разрыве сети
  или остановке между запросом и сохранением ответа результат помечается неизвестным:
  такая отправка автоматически не повторяется. Это предотвращает слепые дубли,
  но не обещает «ровно один раз» при сетевом сбое.
- Отчёт отдельно считает доставленных полностью, ошибки, пропуски и неизвестные
  результаты. История подтверждений доступна в `broadcast_delivery.sqlite3`.
- Новый черновик сохраняет текст, Telegram entities и file_id, а не только ссылку
  на сообщение админа. Удаление исходного сообщения не ломает такой черновик.
  Старые ежедневные черновики без снимка содержимого лучше создать заново.
- Ежедневная отправка использует московское время, сохраняется до отправки
  и запускается один раз за дату. При запуске после назначенного часа бот отправляет
  сегодняшнюю рассылку; пропущенные предыдущие дни не накапливает.
- Заявки сохраняются на диске. Ошибка approveChatJoinRequest больше не считается
  успехом: заявка остаётся в очереди. Расписание приёма также использует Москву.

## Premium-эмодзи и кнопки

Вставьте Premium-эмодзи в текст/подпись приветствия средствами Telegram.
Бот сохраняет исходные entities с UTF-16 offsets, не перекраивает текст.
Это же работает в рассылке. Фото, видео и файлы поддерживают подписи.

В редакторе кнопок приветствия отправьте по одной кнопке на строку:

```
Открыть | https://example.com | зелёный
Подробнее | https://example.org | синий | 1234567890123456789
Отказаться | https://example.net | красный
```

Цвет и ID необязательны. Доступны `зелёный`, `синий`, `красный`, `обычный`.
Premium-эмодзи можно вставить прямо в подпись: первый такой эмодзи становится
иконкой кнопки. Произвольные RGB/градиенты Bot API не поддерживает.

В рассылке: «Добавить кнопку» → отправьте подпись с эмодзи → отправьте
`https://example.com | зелёный` (при необходимости добавьте `| ID`).
Все кнопки отображаются в предпросмотре; управление не попадает получателям.
В админке подтверждения зелёные, опасные действия красные, навигация нейтральная.

Custom emoji в тексте и иконках доступны при Telegram Premium **владельца бота**
для прямых сообщений в личные/групповые чаты либо при дополнительных именах,
купленных через Fragment. Premium получателя не заменяет это требование.
Если Telegram явно отвергает оформление, бот повторяет отклонённый запрос
без неподдерживаемых полей, сохраняет обычный эмодзи/ссылку/остальное форматирование
и показывает причину в журнале, отчёте и меню рассылки.

## Что сохранять на постоянном диске

Существующие `welcome_messages.json`, `bot_settings.json`, `subscribers.json`,
`subscriber_dates.json`, `started_users.json`, `pending_welcomes.json` и новые
`recipient_state.json`, `pending_requests.json`, `broadcast_delivery.sqlite3`.
Не храните их на очищаемой при redeploy файловой системе.
Переменная `BOT_DATA_DIR` задаёт абсолютный путь к постоянному каталогу.
Делайте резервную копию при остановленном боте. `bot.lock` содержит только
межпроцессный замок и автоматически освобождается ОС при завершении.
